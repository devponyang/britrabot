# 아이온2 Discord 관리 봇

Python 3.11 이상이 필요합니다. 인증·알람·공식 공지·아티팩트 기록·티켓을 제공합니다.

## 설치와 실행

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m playwright install chromium
Copy-Item env.example .env
# .env의 DISCORD_TOKEN을 설정합니다.
.venv/Scripts/python bot.py
```

이미 `.env`가 있다면 복사하지 않습니다. 설정 파일은 실행 위치와 무관하게 프로젝트 폴더에서 읽습니다.
Discord Developer Portal에서 SERVER MEMBERS INTENT와 MESSAGE CONTENT INTENT를 켜세요.
봇 초대 시 `bot`, `applications.commands` 범위를 사용합니다.
봇에게 채널 보기·메시지 보내기·임베드 링크·메시지 기록 보기·역할 관리·닉네임 관리·메시지 관리·채널 관리 권한이 필요합니다.
인증 역할은 봇의 최상위 역할보다 아래에 있어야 합니다. 서버 관리자 권한 전체를 부여할 필요는 없습니다.

## 인증

1. `/인증역할설정`으로 실제 부여 가능한 역할을 지정합니다.
2. `/인증서버설정`과 `/인증게시판설정`으로 게임 서버와 공식 HTTPS 게시글 주소를 설정합니다.
3. `/인증패널생성`으로 패널을 게시하거나 `/관리자패널`의 **인증 관리**를 이용합니다.
4. 사용자는 인증진행 → 코드 댓글 작성 → 댓글 작성 완료 순서로 진행합니다.
5. 댓글 작성 완료를 한 번 누르면 해당 개인 메시지의 버튼이 즉시 비활성화되고 진행 중 임베드가 표시됩니다. 성공하면 완료 상태로 잠기며, 실패·오류·시간 초과 시 버튼이 다시 활성화됩니다. 3회 실패 후 10분 대기 제한은 그대로 적용됩니다.
6. 기존에 게시한 인증 패널의 주의사항을 갱신하려면 `/인증패널생성`으로 다시 게시하세요.

- 기본 대상은 브리트라, 전투력 기준은 450입니다. 기준은 `verify.py`의 `MIN_POWER_LEVEL`에서 변경합니다.
- 코드는 안전한 난수 16자리이며 발급 후 30분간 유효합니다. 만료되면 새 코드를 발급해 새 댓글로 작성합니다.
- 댓글의 작성자 프로필에서 서버와 전투력을 확인합니다. ‘이전 댓글 보기’도 탐색하며 최대 30회 화면을 확인합니다.
- 정상 조회에서 코드 없음·대상 서버 불일치·전투력 미달이면 실패 횟수를 추가합니다. 3회 실패하면 10분 대기하며, 대기 종료 후 횟수를 초기화합니다.
- 사이트 오류·전투력 조회 불가·역할 부여 실패는 실패 횟수에 포함하지 않습니다.
- 역할 부여가 성공한 뒤에만 완료로 저장합니다. 닉네임 변경 실패는 별도로 안내합니다.
- 같은 사용자의 중복 클릭을 막고 전체 인증 처리 동시 실행 수를 3개로 제한합니다. 대기를 포함한 처리 제한은 3분입니다.
- 인증 기록은 서버 ID와 사용자 ID별로 분리합니다. 기존 형식은 접근 시 이전하며, 과거의 불확실한 완료 기록은 재확인할 수 있습니다. 이미 받은 Discord 역할은 제거하지 않습니다.
- 기존 기록에 완료로 남았더라도 실제 역할이 없으면 다시 인증할 수 있습니다.
- 폐기된 기존 기본 게시글 주소는 현재 사용 중인 정상 기본 게시글 주소로 읽을 때 보정합니다. 별도로 설정한 다른 주소는 유지합니다.

## 명령어

모든 명령어는 관리자 전용 슬래시 명령어입니다.

| 명령어 | 기능 |
|---|---|
| `/관리자패널` | 채널·알람 문구·인증 관리 패널 |
| `/인증패널생성` | 사용자 인증 패널 게시 |
| `/인증역할설정` | 인증 완료 역할 지정 |
| `/인증서버설정` | 인증 대상 게임 서버 지정 |
| `/인증게시판설정` | 인증 댓글 게시글 지정 |
| `/알람채널설정` | 게임 알람 채널 지정 |
| `/알람메시지설정` | 이벤트별 안내 문구 설정 |
| `/알람메시지설정패널` | 문구 설정 버튼 게시 |
| `/아티설정` | 브리트라 상대 서버 지정 |
| `/아티확인` | 저장된 아티팩트 기록 조회 |
| `/로그채널설정` | 입퇴장·삭제·인증 로그 채널 지정 |
| `/메시지삭제` | 현재 채널의 최근 메시지 1~100개 삭제 |
| `/티켓패널생성` | 문의 티켓 생성 버튼 게시 |

사용자 티켓은 작성자와 서버 관리자만 볼 수 있습니다. 닫기 버튼은 채널을 보관하고 작성자의 메시지 작성을 막습니다. 삭제하지 않습니다.
기존 티켓에 닫기 버튼이 없다면 새 버전에서 생성한 티켓부터 버튼이 표시됩니다.
입장 자동 역할과 환영·퇴장 메시지는 `guild_config.json`의 `autorole`, `welcome_channel`, `leave_channel` 설정이 있을 때 작동합니다.

## 알림과 저장

- 모든 게임 일정은 한국 시간(KST) 기준입니다. 스케줄은 `cogs/automation.py`의 `ALARM_SCHEDULE`에 있습니다.
- 알람은 20초마다 확인하며 최근 5분의 누락을 보완합니다. 아티팩트 수집은 별도 작업으로 실행합니다.
- 아티팩트 상세 기록은 30분마다 동기화하며 기존 회차와 요약을 보존합니다.
- 아티팩트 결과는 수·토 22:30부터 다음 날 03:00 전까지 2분마다 확인합니다.
- 공식 공지는 5분마다 확인합니다. 게시판별 첫 수집은 기존 글을 기준선으로 저장합니다.
- 발송 기록은 JSON에 남겨 재시작 후에도 중복을 억제합니다. Discord 전송 직후 저장 전에 프로세스가 강제 종료되는 경우에는 중복 가능성이 남습니다.
- 특정 서버의 공식 공지 채널은 `cogs/automation.py`, 알람 역할은 `alarm_settings.py`에 있습니다. 다른 서버의 일반 알람 멘션 역할은 관리자 패널에서 설정합니다.
- JSON은 임시 파일 기록·동기화 후 교체합니다. 손상된 파일은 빈 데이터로 덮어쓰지 않고 오류를 기록합니다. 원본을 백업한 뒤 복구해야 합니다.
- JSON 저장소는 **봇 프로세스 한 개**로 운영합니다. 여러 프로세스가 필요하면 트랜잭션 데이터베이스로 이전해야 합니다.

| 파일 | 내용 |
|---|---|
| `guild_config.json` | 서버 설정과 발송 기록 |
| `verify_config.json` | 서버별 인증 설정 |
| `verify_codes.json` | 인증 코드·시도 횟수·완료 기록 |
| `artifact_records.json` | 회차별 누적 기록과 요약 |

설정·인증 JSON과 `.env`는 Git에서 제외됩니다. 정기적으로 별도 백업하세요.

## 검증

```powershell
.venv/Scripts/python -m unittest discover -s tests -v
# 공개 인증 게시글 접근·댓글 추가 로딩·캐릭터 조회를 읽기 전용 점검
.venv/Scripts/python scripts/check_sources.py
# 설치된 Edge로 점검할 경우
.venv/Scripts/python scripts/check_sources.py msedge
```

회귀 테스트는 임시 파일과 모의 Discord 응답을 사용하며 실제 서버에 접속하거나 메시지·역할을 변경하지 않습니다.
브라우저 진단은 사이트 구조와 상태에 따라 실패할 수 있습니다. 콘솔 로그의 원인을 확인하세요.

## 코드 구조

- `bot.py`: 시작·명령 등록·종료
- `verify.py`, `verification_state.py`: 인증 UI·검증 흐름·서버별 상태
- `aion2_scraper.py`: 공식 사이트와 아툴 조회
- `cogs/automation.py`: 일정·공지·기록·관리자 패널
- `cogs/moderation.py`: 삭제 명령
- `storage.py`: 원자적 JSON 저장
- `discord_helpers.py`, `alarm_settings.py`: 공통 UI·티켓·권한 처리·역할 설정
