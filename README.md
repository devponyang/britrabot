# 아이온2 Discord 관리 봇

Python 3.11 이상이 필요합니다. 인증·알람·공식 공지·아티팩트 기록·티켓을 제공합니다.

## 설치와 실행

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m playwright install chromium
Copy-Item env.example .env
# .env의 DISCORD_TOKEN을 설정합니다.
.venv/Scripts/python bot.py
```

이미 `.env`가 있다면 복사하지 않습니다. 설정 파일은 실행 위치와 무관하게 프로젝트 폴더에서 읽습니다.
Discord Developer Portal에서 SERVER MEMBERS INTENT와 MESSAGE CONTENT INTENT를 켜세요.
봇 초대 시 `bot`, `applications.commands` 범위를 사용합니다.
봇에게 채널 보기·메시지 보내기·임베드 링크·메시지 기록 보기·역할 관리·닉네임 관리·메시지 관리·채널 관리 권한이 필요합니다.
인증 역할은 봇의 최상위 역할보다 아래에 있어야 합니다. 서버 관리자 권한 전체를 부여할 필요는 없습니다.

## 인증

이 봇은 Discord 서버 `1545016047332237332`에서만 작동합니다 (`server_scope.py`). 재시작 또는 재연결 시 다른 가입 서버에서 자동 탈퇴하며, 다른 서버에 새로 초대돼도 탈퇴합니다. 탈퇴 API가 실패해도 다른 서버의 자동 작업·명령·버튼 처리는 차단합니다. 슬래시 명령어는 지정 서버에만 등록하며 기존 전역 명령어는 시작 시 제거합니다. 운영 서버에 변경 파일을 반영하고 봇 프로세스를 재시작해야 적용됩니다.

1. `/인증역할설정`으로 실제 부여 가능한 역할을 지정합니다.
2. `/인증서버설정`과 `/인증게시판설정`으로 게임 서버와 공식 HTTPS 게시글 주소를 설정합니다.
3. `/인증패널생성`으로 패널을 게시하거나 `/관리자패널`의 **인증 관리**를 이용합니다.
4. 사용자는 인증진행 → 코드 댓글 작성 → 댓글 작성 완료 순서로 진행합니다.
5. 댓글 작성 완료를 한 번 누르면 해당 개인 메시지의 버튼이 즉시 비활성화되고 진행 중 임베드가 표시됩니다. 성공하면 완료 상태로 잠기며, 실패·오류·시간 초과 시 버튼이 다시 활성화됩니다. 3회 실패 후 10분 대기 제한은 그대로 적용됩니다.
6. 기존에 게시한 인증 패널의 주의사항을 갱신하려면 `/인증패널생성`으로 다시 게시하세요.

- 기본 대상은 브리트라, 전투력 기준은 450입니다. 기준은 `verify.py`의 `MIN_POWER_LEVEL`에서 변경합니다.
- 코드는 안전한 난수 16자리이며 발급 후 30분간 유효합니다. 만료되면 새 코드를 발급해 새 댓글로 작성합니다.
- 댓글의 작성자 프로필에서 서버와 전투력을 확인합니다. ‘이전 댓글 보기’도 탐색하며 최대 30회 화면을 확인합니다.
- 정상 조회에서 코드 없음·대상 서버 불일치·전투력 미달이면 실패 횟수를 추가합니다. 3회 실패하면 10분 대기하며, 대기 종료 후 횟수를 초기화합니다.
- 사이트 오류·전투력 조회 불가·역할 부여 실패는 실패 횟수에 포함하지 않습니다.
- 역할 부여가 성공한 뒤에만 완료로 저장합니다. 닉네임 변경 실패는 별도로 안내합니다.
- 같은 사용자의 중복 클릭을 막고 전체 인증 처리 동시 실행 수를 3개로 제한합니다. 대기를 포함한 처리 제한은 3분입니다.
- 인증 기록은 서버 ID와 사용자 ID별로 분리합니다. 기존 형식은 접근 시 이전하며, 과거의 불확실한 완료 기록은 재확인할 수 있습니다. 이미 받은 Discord 역할은 제거하지 않습니다.
- 기존 기록에 완료로 남았더라도 실제 역할이 없으면 다시 인증할 수 있습니다.
- 폐기된 기존 기본 게시글 주소는 현재 사용 중인 정상 기본 게시글 주소로 읽을 때 보정합니다. 별도로 설정한 다른 주소는 유지합니다.

## 명령어

### 버튼식 파티 모집·레기온 홍보

관리자가 `/모집패널설정`을 실행하면 `1548041064961810482` 채널에 통합 패널 하나를 설치합니다. 파티 모집 작성·레기온 홍보 작성 버튼이 함께 표시됩니다. 재실행하면 기존 통합 패널을 수정하며 이전 버전에서 저장한 개별 패널은 정리합니다. 파티 글은 `1547063601611804803`, 레기온 홍보는 `1547063786320568350`에 게시합니다. 각 채널에서 봇의 보기·메시지 보내기·임베드 링크·기록 보기 권한을 확인하세요.

사용자는 슬래시 명령어 없이 **작성 버튼 → 입력창 → 모집글 버튼**으로 이용합니다.

- 파티: 콘텐츠·조건·정원·출발 시각 입력, 참가·참가 취소·수정·종료·재개 버튼. 정원은 모집자를 포함해 2~24명입니다. 정원이 차면 추가 참가를 막고 취소 시 다시 모집합니다. 출발 시각이 지나면 1분 이내 종료 상태로 표시됩니다.
- 레기온: 이름·소개·가입 조건·활동 시간·문의 방법 입력, 수정·종료·재개 버튼. 작성자 멘션을 문의 대상으로 표시합니다.
- 종류별 한 사람당 진행 중인 글 하나만 허용하며 같은 레기온 이름의 중복 홍보를 제한합니다. 수정·종료·재개는 작성자와 관리자만 가능합니다.
- 버튼은 재시작 후에도 작동합니다. 정보는 `recruitment.json`에 저장합니다. 모집글은 임베드만 표시하며 참여할 때마다 새 공개 메시지를 보내지 않습니다.
- 인증 회원 전용으로 운영하려면 패널 채널과 게시 채널의 보기·메시지 권한을 서버에서 설정하세요.

### 쿠폰 관리

쿠폰 입력·정보·삭제 명령어는 모두 관리자 전용입니다.

```text
/쿠폰입력 code:EXAMPLE2026 expires:2026-09-30 23:59
/쿠폰정보
/쿠폰삭제 code:EXAMPLE2026
```

`/쿠폰입력`은 번호와 유효기한을 저장합니다. 날짜만 입력하면 해당 날짜 한국 시간 23:59:59까지로 처리합니다. 같은 번호는 대소문자를 구분하지 않고 유효기한을 갱신합니다. 번호는 영문·숫자·하이픈·밑줄 1~64자를 지원합니다.

`/쿠폰정보`는 실행 채널에 모두가 볼 수 있는 임베드 하나를 게시합니다. 같은 채널에서 재실행하면 기존 메시지를 재사용합니다. 여러 채널에 게시한 경우 새 쿠폰 등록 시 모두 수정됩니다. 등록 전에도 빈 정보 패널을 게시할 수 있습니다.

쿠폰 데이터와 메시지 ID는 `coupons.json`에 저장합니다. 만료 상태는 1분마다 갱신하며 수정 실패도 재시도합니다. 한 메시지에 사용 가능한 쿠폰 최대 25개를 지원하고, 새 쿠폰을 등록할 때 만료된 항목을 정리합니다. 봇에게 메시지 보내기·임베드 링크·기록 보기 권한이 필요합니다.

`/다음알람`, `/내음성방이름`은 일반 사용자도 사용할 수 있습니다. 나머지는 관리자 전용입니다.

| 명령어 | 기능 |
|---|---|
| `/관리자패널` | 채널·알람 문구·인증 관리 패널 |
| `/인증패널생성` | 사용자 인증 패널 게시 |
| `/인증역할설정` | 인증 완료 역할 지정 |
| `/인증서버설정` | 인증 대상 게임 서버 지정 |
| `/인증게시판설정` | 인증 댓글 게시글 지정 |
| `/알람채널설정` | 게임 알람 채널 지정 |
| `/알람멘션설정` | 10분 전·시작 / 시작만 / 전체 / 멘션 없음 선택 |
| `/다음알람` | 다음 일정 5개를 본인에게만 표시 |
| `/개인음성설정` | 입장용 음성채널 지정 및 자동 생성 켜기·끄기 |
| `/내음성방이름` | 본인이 만든 음성방에서 이름 변경 |

| `/로그채널설정` | 입퇴장·삭제·인증 로그 채널 지정 |

사용자 티켓은 작성자와 서버 관리자만 볼 수 있습니다. 닫기 버튼은 채널을 보관하고 작성자의 메시지 작성을 막습니다. 삭제하지 않습니다.
기존 티켓에 닫기 버튼이 없다면 새 버전에서 생성한 티켓부터 버튼이 표시됩니다.
입장 자동 역할과 환영·퇴장 메시지는 `guild_config.json`의 `autorole`, `welcome_channel`, `leave_channel` 설정이 있을 때 작동합니다.

## 알림과 저장

- 모든 게임 일정은 한국 시간(KST) 기준입니다. 스케줄은 `cogs/automation.py`의 `ALARM_SCHEDULE`에 있습니다.
- 알람에 실제 시작 시각·남은 시간을 표시합니다. 기본 멘션은 10분 전과 시작에만 전송합니다. 30분 전에는 안내만 표시하며 `/알람멘션설정`으로 변경할 수 있습니다.
- 아티팩트쟁은 수·토 22:00로 정리했습니다. 종전의 16~22시 매시간 시작 알람은 없앴으며 어비스 필드보스 22:30은 별도로 안내합니다.
- 알람은 20초마다 확인하며 최근 5분의 누락을 보완합니다. 아티팩트 수집은 별도 작업으로 실행합니다.
- 아티팩트 상세 기록은 30분마다 동기화하며 기존 회차와 요약을 보존합니다.
- 아티팩트 결과는 수·토 22:30부터 다음 날 03:00 전까지 2분마다 확인합니다.
- 지정 서버의 아티 결과 채널은 `1547489396301762640`입니다. 일반 공식 공지의 기타 채널은 별도입니다.
- `/아티확인`은 현재 매칭을 조회해 저장합니다(120초 캐시). 조회 실패 시 가장 최근 저장 상대를 표시하며 `/아티설정`은 최신 기록이 없는 경우의 기본값입니다. 과거 상대는 `/아티확인 server:루드라`처럼 조회합니다.
- 2026-09-09 22:00 1차전은 브리트라 2:4 네자칸으로 공개 원본에서 확인했습니다. 회차 점수와 누적 점수를 구분하며 요약이 없어도 회차 기록을 표시합니다.
- 공식 공지는 5분마다 확인합니다. 게시판별 첫 수집은 기존 글을 기준선으로 저장합니다.
- 발송 기록은 JSON에 남겨 재시작 후에도 중복을 억제합니다. Discord 전송 직후 저장 전에 프로세스가 강제 종료되는 경우에는 중복 가능성이 남습니다.
- 특정 서버의 공식 공지 채널은 `cogs/automation.py`, 알람 역할은 `alarm_settings.py`에 있습니다. 다른 서버의 일반 알람 멘션 역할은 관리자 패널에서 설정합니다.
- JSON은 임시 파일 기록·동기화 후 교체합니다. 손상된 파일은 빈 데이터로 덮어쓰지 않고 오류를 기록합니다. 원본을 백업한 뒤 복구해야 합니다.
- JSON 저장소는 **봇 프로세스 한 개**로 운영합니다. 여러 프로세스가 필요하면 트랜잭션 데이터베이스로 이전해야 합니다.

| 파일 | 내용 |
|---|---|
| `guild_config.json` | 서버 설정과 발송 기록 |
| `verify_config.json` | 서버별 인증 설정 |
| `verify_codes.json` | 인증 코드·시도 횟수·완료 기록 |
| `artifact_records.json` | 회차별 누적 기록과 요약 |
| `voice_rooms.json` | 개인 음성방 입장 채널·방 소유자 |

설정·인증 JSON과 `.env`는 Git에서 제외됩니다. 정기적으로 별도 백업하세요.

## 임베드가 보이지 않을 때

`/아티확인` 전적은 본문 중복 없이 임베드로만 표시합니다. 기록이 Discord의 임베드 길이 제한을 넘으면 여러 페이지로 나눕니다.

사용자의 Discord 설정에서 **임베드 및 링크 미리보기 표시**가 꺼져 있으면 버튼만 보일 수 있습니다. 사용자 설정의 채팅/표시 관련 메뉴에서 켜고 다시 확인하세요. 모두에게 안 보인다면 봇의 해당 채널 **임베드 링크** 권한도 확인합니다.

인증·알람·공지·각종 패널은 본문 중복 없이 임베드만 표시합니다. 알람의 역할 멘션만 임베드 위에 별도로 표시됩니다. 임베드를 숨긴 사용자는 Discord의 임베드 표시 설정을 켜야 본문을 볼 수 있습니다. 이미 발송한 알람은 자동 수정하지 않습니다. 기존 인증 패널은 `/인증패널생성`으로 다시 게시하고, 이전 개인 인증 안내는 **인증진행**을 다시 눌러 새로 받으세요. 사용자 화면 설정을 봇이 강제로 바꾸지는 못합니다.

## 개인 음성방

관리자가 `/개인음성설정 channel:입장용채널`을 한 번 실행합니다. 봇에게 해당 카테고리와 입장 채널의 **채널 관리·멤버 이동·채널 보기·연결** 권한이 필요합니다. 입장용 채널은 먼저 서버에 만들어 두세요.

사용자가 입장하면 같은 카테고리에 방을 만들고 이동합니다. 방 주인은 해당 방에 들어간 상태에서 `/내음성방이름 name:새 이름`으로 변경합니다. 전체 채널 관리 권한을 사용자에게 부여하지 않습니다. 이름 변경 간격은 310초, 새 방 생성 간격은 30초이며 서버당 자동 방은 최대 50개입니다. 재입장하면 기존 방으로 이동합니다.

비어 있는 자동 생성 방만 삭제하며, 재시작 후에도 저장된 소유자 정보를 사용해 2분마다 정리합니다. 기존 일반 음성채널은 삭제 대상이 아닙니다. 실제 사용할 입장 채널 ID는 아직 지정하지 않았습니다.

## 검증

```powershell
.venv/Scripts/python -m unittest discover -s tests -v
# 공개 인증 게시글 접근·댓글 추가 로딩·캐릭터 조회를 읽기 전용 점검
.venv/Scripts/python scripts/check_sources.py
# 설치된 Edge로 점검할 경우
.venv/Scripts/python scripts/check_sources.py msedge
# 실제 아티팩트 수집기로 최신 결과와 과거 기록 표를 읽기 전용 확인
.venv/Scripts/python scripts/validate_artifacts.py
```

회귀 테스트는 임시 파일과 모의 Discord 응답을 사용하며 실제 서버에 접속하거나 메시지·역할을 변경하지 않습니다.
브라우저 진단은 사이트 구조와 상태에 따라 실패할 수 있습니다. 콘솔 로그의 원인을 확인하세요.

## 코드 구조

- `bot.py`: 시작·명령 등록·종료
- `verify.py`, `verification_state.py`: 인증 UI·검증 흐름·서버별 상태
- `aion2_scraper.py`: 공식 사이트와 아툴 조회
- `cogs/automation.py`: 일정·공지·기록·관리자 패널
- `cogs/moderation.py`: 삭제 명령
- `storage.py`: 원자적 JSON 저장
- `discord_helpers.py`, `alarm_settings.py`: 공통 UI·티켓·권한 처리·역할 설정

## 추가 운영 보호

- 알람 역할 변경 중 같은 버튼을 연속으로 누르면 중복 요청을 차단하며, 실패 후에는 다시 시도할 수 있습니다.
- 삭제된 모집글과 채널은 5분마다 확인해 기록에서 제거합니다. 내용이 그대로인 글은 확인만 하고 수정하지 않습니다.
- `/쿠폰삭제`는 잘못 등록한 쿠폰을 삭제하고 기존 쿠폰 정보 메시지도 갱신합니다.
